## 一、核心架构缺陷（高危）

### 1.1 Page 块导致整卷真实存储丢题 ⚠️ **最严重**
**影响范围**：create 和 update 两条链路\
**触发条件**：文档包含任意 page 声明（`page { ... };` 块语法 或 `node "Question" { attr "Type" = "page"; ... }`）

**表现**：
- 服务端无任何报错，正常返回 vid，问卷以草稿状态建出
- 编辑器/答卷页打开后**整卷空白或只剩一排空分页栏**
- 真实存储中题目数 = 0，或仅剩空壳条目（`q_type=1, q_subtype=1, q_title="", q_index=0`）
- DSL 文档里的所有题目一个都不落盘

**验证失真**：
- 此前所有依赖「延时 DSL 回读」的验证（25 秒 + 20 秒双查询）全部显示通过
- 缺陷被完全掩盖，直到用户人工打开才发现

**实例**：
- 用户 219901 原话：「全部显示是分页栏」
- 219897 vs 219899 对照实验

---

### 1.2 影子回读与 CLI 验证失真 ⚠️
**问题本质**：两套数据、两个世界

**现象**：
1. `wjx dsl query` 延时回读返回的是**影子文档视图**：
   - 坏卷（真实存储 0 题）也能"完整回读"全部题目、属性、Topic 编号
   - 与服务端实际存储完全脱钩

2. `wjx survey get --get_questions` 才是编辑器同款的**真实存储**

3. CLI 自带读回验证读的也是影子，且结论**双向失真**：
   - 报「成功」→ 实际整卷丢（**假阳性**）
   - 报「结果未知」→ 实际已成功落盘（**假阴性**，219901/219449/219891）
   - 报 `ok=true + outcome=verified + actualQuestionCount=4` → 真实存储只有 1 题（**verified 误判**，219808）

**结论**：CLI 的成功/结果未知/verified 三种结论**都不能作为写入是否生效的判据**

## 二、题型别名与验证机制问题

### 2.1 别名机制不完整、不统一
**问题**：有的题型靠别名、有的靠中文 Verify、有的靠 Type 属性，**没有一致的规律**

**缺失覆盖**：
- `citylevel`（城市级别）：正确写法是裸 `question + Verify="城市级别"`（vid=219514 verified）
- `cati`（CATI 调研）：正确写法是 `node "Question" + Type="cati"`（vid=219512 verified）或 `radio_cati` 别名 + ≥1 个 Item

**误导行为**：
- 未知别名默认按 `radio` 校验，易误导
- 例如 `citylevel` 别名被按 radio 处理并报「至少需要一个 Item」
- 建议诊断信息直接提示「别名未识别，已按 radio 处理」，或扩充别名表

---

### 2.2 同一题型两种声明形态能力不对等
**问题题型**：fold/clock/cut/carousel/funnel/heatmap

**现象**：
- **alias 形态**一律被 `DSL_QUESTION_ALIAS_TYPE` 拒绝
- **node 形态**可用：改写为 `node "Question"` 并以 `attr "Type" = "<别名>"` 声明类型后创建成功
  - 结构配置类：vid=219511
  - 轮播图 + 漏斗：vid=219508

**报错**：笼统的「DSL 未通过严格校验」，不提示该改用 node 形态

**建议**：规范应统一两种形态或明确标注哪些题型必须 node

---

### 2.3 解析器接受 raw attr，服务端整单拒绝
**问题**：
- 解析器接受 `raw attr` 语句（语料里就有）
- 服务端不识别：`raw attr "OnePageOneQuestion" = "true"` 触发「无法识别的语句」整单被拒
- **解决方案**：去掉 `raw` 前缀，以普通 attr 写入后通过

## 四、预置题型数据处理不当

### 4.1 Kano 模型题
**问题**：预置了行标题和列标题，按功能点添加题目；DSL 添加的结构不对，把预置的行标题改成了功能点

### 4.2 价格相关题型（价格断裂点、MaxDiff、BWS、联合分析、PSM）
**问题**：这几个题型有预置的内容，DSL 创建时好像不知道

**详细说明**：
- **价格断裂点**：自定义 3 档接受度选项 → 归一为「购买意愿」5 级（反而更贴合方法论）
- **MaxDiff**：按"组标签行"提交 → 服务端展开为 6 行 / 3 列 / 5 选项
- **BWS**：自选 2 项（最好/最差）→ 归一为 5 选项
- **联合分析**：1 个占位行 → 自动展开 12 个组合卡片行（按 TaskCount×Length）
- **PSM**：纯填空 4 行（无选项提交）→ 回读出现 5 个标准选项

## 五、编辑问卷功能限制

### 5.1 有回收答卷的问卷拒绝一切结构性修改
**问题**：这个需要写入 DSL 或者什么地方吗？

### 5.2 AI 编辑问卷行为不一致
| 场景 | AI 行为 | 实际情况 |
|------|---------|----------|
| 问卷已有答卷，要求 AI 增加题目、选择 | 不会进行操作 | 实际有答卷后是可以修改题目、选项内容的 |
| 问卷已有答卷，要求 AI 修改题型 | 拒绝修改 | 实际是可以手动修改成功的 |

## 六、题型设置与字段缺失

### 6.1 基本信息题
**问题**：添加的基本信息题和页面上的不一样
- 页面上添加时是**矩阵填空题型**
- DSL 添加的是**填空题**

### 6.2 Vlookup 题型
**问题**：设置查询题目设置不成功

### 6.3 多项文件、多项简答题
**问题**：不能增删行标题

### 6.4 编辑问卷预览
**问题**：问卷已有答卷，要求修改问卷题目、选择，现在都不会进行操作（实际可以修改）

## 七、总结与建议

### 高优先级修复项（P0）
1. **Page 块丢题问题**：整卷存储失败，用户完全不可见，极其危险
2. **影子回读验证失真**：CLI 验证结果完全不可信，需切换到真实存储校验
3. **别名机制统一**：建立完整的题型别名表，统一声明形态

### 中优先级修复项（P1）
4. 考试类题型分值计算错误
5. 特殊题型（签到、热力图、BWS、品牌漏斗、CATI 等）映射错误
6. OCR 题型字段识别与属性设置问题
7. 预置题型（Kano、价格相关）数据处理

### 低优先级优化项（P2）
8. 填空题部分属性支持（手机验证、日期与时间完整支持）
9. AI 编辑问卷行为优化
10. 商品题/预约题/货架题自动配置优化

### 需要产品决策的问题
- 360 评估、教学评估是否需要支持？
- 答题录音、答卷摄像是否需要保留？
- 智能阅卷 `is_ai_grading` 是否需要开放支持？
- 有回收答卷的问卷修改限制如何在 DSL 层面体现？
