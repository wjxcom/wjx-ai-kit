# 题目逻辑：方向、引用和随机

问卷关联、显示隐藏、跳题、引用和随机逻辑统一使用 `dsl.logic`，创建与修改均适用。JSONL 只定义问卷基础信息、题目内容与题型配置，不要在其中新增、复制或修改 `relation`、`referselect`、跳转、引用、随机等逻辑字段，也不要用 JSON 字段和 DSL 重复表达同一逻辑。

创建有逻辑的问卷时，将完整 JSONL 与 `"dsl":{"logic":"logic { ... };"}` 一起提交；修改前先读取问卷，再基于返回的 `dsl.logic` 提交同一问卷的逻辑。仅修改逻辑时只提交 `vid + dsl`，不回写 JSONL 或查询中的历史逻辑字段。外层请求及 `--dsl` 参数中的 JSON 对象只是参数容器，逻辑规则本身必须是 DSL 文本。

若当前 CLI 或服务端的 DSL 不支持所需逻辑，或逻辑校验失败，明确说明限制，不得改用 JSON 逻辑字段绕过，也不得省略该逻辑后宣称完成。不要把问卷基础信息、题目定义或计算公式放进 `dsl.logic`。

## 先确定真实题号

逻辑中的数字是实际 `q_index`，选项号是从 1 开始的选项顺序，不是选项分值。`S1`、`T1` 等题干标签不是逻辑标识。分页和段落不是条件来源；它们的编号也不能当作真实题号。

新建问卷的第一道真实题从 1 编号，基础信息、分页和段落不占真实题号。创建后和每次编辑后，均以 `survey get` 返回的题目、选项和 `dsl.logic` 再次核对。修改已有问卷时使用查询返回的真实编号，不要自行重编号。

历史问卷若因基础信息占号而从 2 开始，仅修改逻辑仍使用查询返回的原题号。无论是否已有答卷，当前都不自动迁移旧题号，编辑器也不会因此自动同步重编号或修复保存兼容性。发现编辑后题号或逻辑变化时，应停止重复保存并保留问卷编号排查，不能把新建编号修复当作旧问卷已修复。

所有依赖必须朝向后面的题目：

- 题目、选项的显示条件只能依赖前面的题目。
- 选项、行标题、题干引用和答案自动填入只能由后题引用前题。第一题不能引用后题。
- 跳题只能从前题跳到后题，或跳到 `END`。

## 题目和选项关联

假设实际题号 2 是身份，选项 1 为学生、选项 2 为在职；实际题号 3 是学校：

```text
logic {
  if "2::1" then show "3";
};
```

学校只在选择学生时显示，其他情况自动隐藏，无须再增加一条隐藏规则。若用 `if "2::2" then hide "3";`，其含义是“选择在职时隐藏”，会保存为等价的否定显示条件。

选项关联在目标后加选项顺序。以下只控制第 3 题的第 1 个选项，第 2、3 个选项保留原显示状态：

```text
logic {
  if "2::1" then show "3::1";
};
```

多个可选条件应写进同一表达式，例如 `if "2::1" or "2::2" then show "3";`。同一目标的多条条件会共同约束该目标，不能用多条 `show` 代替 `or`。`show "3";` 清除该题显示条件，`hide "3";` 将其设为始终隐藏。

## 选项引用和行标题引用

`from` 永远是前面的来源题，`to` 永远是后面的接收题。不要把“接收题引用来源题”翻译成相反的参数方向。

来源题使用多选或排序题。选项引用使用 `options`；矩阵行标题引用使用 `rows`，不要混用：

```text
logic {
  reference options from "2" to "3";
  reference rows from "2" to "4";
};
```

上例中，第 3 题的选项和第 4 题的矩阵行来自第 2 题。接收题的内容与来源选项顺序保持对应，作答时根据来源题的选择显示；不是从后面的题目向前引用。

## 题干文本引用

题干引用使用 `title`，接收题题干必须先包含对应的 `[qN]` 占位符：

```jsonl
{"qtype":"问卷基础信息","title":"渠道体验调查"}
{"qtype":"单选","title":"S1购买渠道","select":["线上","门店"]}
{"qtype":"简答题","title":"请描述您选择的[q1]渠道的服务体验"}
```

上例来源题的实际编号是 1、接收题是 2，对应逻辑为：

```text
logic {
  reference title from "1" to "2";
};
```

不能只设置 `reference title` 而不放占位符，也不能把 `[q1]` 当作公式计算。

## 答案自动填入

“将第 5 题答案自动填入第 6 题答题框”使用 `answer`：

```text
logic {
  reference answer from "5" to "6";
};
```

来源题必须是前面的普通单选、下拉或普通填空题；接收题必须是后面的普通填空题（单项填空或简答题）。仅支持整题引用，不支持多选、矩阵、子项、带特殊校验的填空题、考试填空或 `raw`；同一接收题只能指定一个答案来源。

第 5 题所选选项的文字或填空答案会填入第 6 题答题框，第 6 题标题保持原文。答题框允许手工修改，来源答案变化时重新同步。接收题题干无需 `[q5]`；不要用 `reference title`、题干占位符或 JSON 逻辑字段代替。服务端未部署此能力或读回缺少该规则时，报告未验证，不得宣称已生效。

## 题目、选项与行随机

题目随机使用实际题号范围；以下从第 2～4 题中随机显示 1 题：

```text
logic {
  random questions mode 4 from "2" ~ "4" count 1;
};
```

省略 `count` 表示保留范围内全部题目并随机排序；指定时必须为不超过范围题数的正整数。省略 `mode` 使用模式 4。范围起点、终点和抽取数量都必须从保存结果读回确认。

```text
logic {
  random options on "2";
  random rows on "4";
};
```

`options` 打乱选择题选项；`rows` 打乱矩阵行。不要用 `options count` 表示抽取若干选项。

## 分页随机

分页随机按问卷中分页节点的顺序从 1 编号，每页及其全部题目作为整体移动，页内题目顺序保持不变。以下从第 1～3 页随机显示 2 页：

```text
logic {
  random pages mode 6 from "1" ~ "3" count 2;
};
```

省略 `mode` 使用模式 6；省略 `count` 表示保留范围内全部分页并随机排序。分页节点必须完整，且各页原生编号与顺序一致。页号不能替换成题号；特殊分页或无法完整读回的分页不能被验证为成功。

同一问卷不能混用题目随机与分页随机，随机区段之间也不能重叠。切换已有随机类型请先在编辑器中清除原配置，避免丢失已有范围。旧模式与未经确认的随机模式不可直接写入；接口明确拒绝时停止，不重复提交相同配置。

不要用 `raw attr` 直接写入根级 `RandomMode`、`PartSet`、`RandomBegin`、`RandomEnd`、`DisplayPart`、`DisplayPartNum`、`RandomPartSame`，或题目级 `RandomChoice`、`RandomRow` 来绕过校验。旧问卷读回的这些原生字段可以保留在查询结果中，但新设置只使用已验证的结构化随机规则。

## 保存后核对

检查真实保存的 `dsl.logic`、题号、选项与引用内容。请求成功但逻辑缺失、方向错误、随机范围或数量不符时，必须报告未验证，不得宣称设置成功。编辑页仍会清除逻辑或作答页不生效时，应停止重复写入并保留问卷编号排查。
